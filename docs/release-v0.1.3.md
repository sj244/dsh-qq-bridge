# v0.1.3 — 维护性更新

本次以修复与文本规范为主，另有 1 项安全修复。功能无新增；行为有 3 处变化，见下。

### 安全

**本机接口校验请求来源**：设置接口与 NapCat 路由原来只校验对端是回环地址。
用户浏览器里的任意网页都能用无预检的 `fetch` 打到本机端口。响应读不到，但改白名单、改目标会话、
启动 NapCat 这些副作用照发生。现在两道路由组共用一道闸门：对端地址 → 来源（`Origin`，
无 `Origin` 时看 `Referer`）→ 带体 POST 的 `content-type`。
空体的 POST 不要求 `content-type`，由来源判定兜住。
原来直接显示在卡片上的英文错误码改为中文。

### 行为变化

**超长出站改为拒绝发送**：原来把超过 `replyMaxChars` 的正文分段发出。现在一条都不发，
返回 `reason: 'too-long'` 与实际上限、字数，让模型缩短后重发。QQ 本就不应发送长消息。

**设置卡片支持撤销覆盖**：设置文件的值优先于插件配置页。原来卡片只写不删，
用户从插件配置页改了不生效，也无处重置。现在被覆盖的字段旁有「撤销覆盖」按钮。

**省略条数反映真实丢失量**：未唤醒摘要原来只统计入选区间内没装下的条目，
窗口外被删的条目不计入。现在统计真实不入摘要的条数；大于 99 时写「更早的大量消息已省略」，
不让巨大数字进入上下文。

### 修复

- **唤醒失败不再记账为成功**：投递抛错时台账改记 `wake-failed` 并带原因，同时回滚轮次归属标志。
  投递 Promise 的异步失败也被接住。
- **视觉模型缓存改为按设置签名**：改 `visionModel` 立刻生效；解析失败的结果在设置变化时丢掉并重试。
- **提示词重挂判据改为设置签名**：改「出站字数上限」后提示词会重挂。
  原来只按 `replyMode` 判断，会出现模型按旧上限写字、出站全被丢弃且模型不知情的情况。
- **目标会话被卸载后不再复用死句柄**：改为按对象同一性验活，失效就走 `resume`。
- **标记块出站被拒时新增独立丢弃台账**：在 `qq_bridge_status` 的 `recentDropped` 暴露，
  并用 `agent.inject()` 把原因回注会话，模型不再以为已经回复。工具路径被拒也进同一份台账。
- **图片占位符与描述一一对应**：落盘失败的图保留占位符，后面的图不顶位。
- **群聊判据改用 `groupId`**：取不到群名时写「群 `<群号>`」，不再误标「私聊」。
- **视觉模型列举失败记 warn**：不再静默当成「没有视觉模型」。
- **出站台账只记真正发出去的消息**：被拒的不写 `outbox`，避免事后对不上账。
- **修 npm 打包缺陷**：`package.json` 的 `files` 缺 `stickers.js`，按该表打包会缺文件、加载失败。

### 文本与文档

- 文档里 10 类与事实不符的说法已修正：版本号、`recentChatLimit` 默认值、超长由分段改为拒发、
  白名单已改空、M3 已完成、文件清单尺寸等。
- 对外文档与代码注释里的直角引号与半角引号统一为全角双引号；行内代码与代码块内的字面值保留。
- 公开仓库脱敏：真实群号、QQ 号、私人昵称与本机路径换成占位值。

### 测试

四个套件共 **498 条断言**，零依赖、纯离线运行；本版新增 137 条（361 → 498）。

### 已知限制

- 出站闸门的多标志协作尚未重构（真机出过 3 次哑火，当前行为有测试兜住）。
- 个别分支仍无断言覆盖：异步投递失败的退化路径、NapCat `/reveal` 的通过路径、
  `write-failed` 分支、`Origin: null`。
